# LA Space Interiors

Luxury interior-design site — fixed navbar, shared footer, and five pages:
Home (10 sections), About (5 sections), Services (6 service blocks), Projects
(filterable 12-item portfolio) and Contact (enquiry form + location band).
React 18 + Vite multi-page build, plain CSS, no UI framework and no animation
library.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # → dist/
npm run preview
npm run images   # re-process public/images after adding client photography
```

## Environment

Copy `.env.example` to `.env` and adjust. Only `VITE_`-prefixed values reach
browser code, and they are baked in at build time, so a change means a rebuild.

| Variable | Default | What it does |
|---|---|---|
| `VITE_DEV_PORT` | `5173` | Dev server port |
| `VITE_API_PROXY_TARGET` | `http://localhost:4000` | Where the dev server forwards `/api` and `/media` |
| `VITE_API_BASE` | `/api` | Where the browser posts enquiries. Same-origin in production, where the API serves the site |
| `VITE_SITE_URL` | `https://www.laspaceinteriors.in` | Canonical origin for `site.url` and the emitted `site-data.json` |

## Images

Drop client photography into `public/images/` under the existing filenames,
then run:

```bash
npm run images
```

It downscales anything over 1700px on the long edge, rewrites the JPEG
optimised, emits a `.webp` sibling, and records every file's intrinsic
dimensions to `src/data/imageMeta.json`. [Img.jsx](src/components/Img.jsx)
reads that manifest, so each `<img>` ships with `width`/`height` and nothing
reflows as images arrive. Re-run it whenever the photography changes; it works
in place and is safe to run repeatedly.

The brand logo and monogram are SVG, so they need no processing — they stay
sharp at any size and weigh under 1KB each.

## Responsive

One breakpoint, **920px**, used by `matchMedia` for exactly two behavioural
switches: navbar mode and the sticky action bar. Everything else reflows
through `repeat(auto-fit, minmax(Xpx, 1fr))` — there are no content media
queries anywhere in the CSS.

Two notes on making that hold down to 360px:

- Any `minmax()` floor wider than a phone must be written
  `minmax(min(420px, 100%), 1fr)`. A bare `minmax(420px, 1fr)` keeps its floor
  when the container is narrower and pushes the page sideways.
- The offset gold image frames sit at `inset: -20px`, i.e. **outside** their
  image. Shot wrappers therefore reserve that room with
  `width: min(var(--shot-w), calc(100% - 48px))`, otherwise the frame is
  clipped on a narrow column. Same for `.arch` on the home page.

## Design tokens

Do not substitute. Colours, sizes and timings are locked to the approved spec in
`tokens.css` and the per-area stylesheets — gold `#C29D62`, gold-dark `#8A6D3F`,
cream `#F2EDE6`, taupe `#C4AD93`, black `#000000`, off-black `#0D0C0A`.
Cormorant Garamond for display, Jost for UI. Single breakpoint: **920px**.

## Header dropdowns

On desktop (above 920px) the `Services` and `Projects` nav items open a
hover dropdown ([Navbar.jsx](src/components/Navbar.jsx), styles at the end of
[navbar.css](src/styles/navbar.css)): a `#0D0C0A` panel flush under the header,
24px left of the label, fading in while dropping 8px (0.3s), items filling
gold on hover. The menu is always mounted and animates between its two
states; one is open at a time; keyboard focus opens it and Escape closes it.
Services lists the published services — the sections on `/services` carry
`id="c0"…` in display order and the page scrolls to the hash 24px below the
header on load and on `hashchange`. Projects lists the category filters in
use; `/projects?f=Kitchen` opens on that filter (unknown → All). Below 920px
nothing is rendered; the hamburger menu is unchanged.

## Entry loader

The home page opens on a full-screen black overlay: the monogram dead
centre, a `000 → 100` counter bottom-right that climbs in irregular steps
(~1.5 s), a 400 ms pause, then the overlay slides up and off (1.1 s,
`cubic-bezier(.77,0,.18,1)`) while the hero headline words rise out of their
masks. The markup and its first-paint styles are inline in `index.html`, so
it is on screen before any script runs; [preloader.js](src/lib/preloader.js)
drives it and [preloader.css](src/styles/preloader.css) holds the rest.

When it shows: on arrival from outside the site (typed URL, search result,
link from elsewhere) and on every reload of the home page. Not when the
visitor comes to the home page from another page of the site, and not on
back/forward. The head script decides from the navigation type and the
referrer. One switch in `src/data/site.js`, applied to the HTML by the
Vite plugin: `preloader.enabled: false` removes the loader entirely —
straight to the page (development).

Reduced motion keeps the counter but drops the slide and the rise. The
monogram is `public/brand/monogram.png` (transparent, 260 px, the mark
without its disc).

## Motion

All animation is CSS transitions plus `IntersectionObserver`:

- Scroll reveal — one-shot, unobserves after firing; threshold `0.1` on Home
  and About, `0.08` on Services, whose blocks are taller ([useReveal.js](src/hooks/useReveal.js)).
  Projects and Contact deliberately have **no** reveal — the Projects grid
  re-renders on filter changes, and Contact is all near the fold
- Stat count-up — threshold `0.3`, 1600ms, ease-out-cubic, fires once ([Stats.jsx](src/components/sections/Stats.jsx))
- Hero carousel — 6000ms auto-advance, restarts on pass click ([Hero.jsx](src/components/sections/Hero.jsx))
- Partner ribbon — doubled list, `translateX(-50%)` over 36s

`prefers-reduced-motion: reduce` skips the reveal, hero autoplay, marquee and
scroll-cue pulse, and jumps the counters straight to their final values.

## SEO

- Head meta ships in the static HTML, not injected by React, so a crawler gets
  title, description, canonical and social cards with zero JS execution.
- Structured data is built by the studio API from the same database rows the
  page shows (`la_space_backend/src/pages/structured-data.ts`), so the FAQ
  markup can never drift from the FAQ copy on screen. Six graphs on the home
  page: InteriorDesignBusiness, WebSite, FAQPage, BreadcrumbList and two
  ItemLists.
- Semantic landmarks (`header` / `nav` / `main` / `footer`), one `h1`, ordered
  heading levels, descriptive `alt` on every content image, `alt=""` on
  decorative ones, `aria-label` on icon-only buttons, `aria-expanded` +
  `aria-controls` on FAQ triggers, and a skip link.
- First hero frame is `fetchpriority="high"`; everything below the fold is
  `loading="lazy"`.
- `npm run budget` runs Lighthouse (mobile) against the API-served site and
  fails under the budget: projects page ≥ 90, home ≥ 80. CI runs the same.
- `public/robots.txt` ships with the build; `/sitemap.xml` is generated by the
  API from the published pages and projects.
- Fonts are self-hosted from `public/fonts` (latin + latin-ext woff2), so there
  is no render-blocking third-party request on the critical path. The two faces
  that always paint above the fold are preloaded in `index.html`.

- Each page gets its own structured data: Home carries FAQPage and two
  ItemLists; About carries AboutPage + Person (the founder); Services carries
  CollectionPage plus a `Service` per discipline with its scope as an
  OfferCatalog; Projects carries CollectionPage plus a CreativeWork per
  project; a project page carries its own CreativeWork with every render;
  Contact carries ContactPage + ContactPoint with opening hours.

### Clean URLs

In production the studio API serves the build: `/about`, `/services`,
`/projects`, `/projects/<slug>` and `/contact` come from `dist/*.html` with
the published content injected, and `/<page>.html` redirects to the clean
URL. The `cleanUrls` plugin in `vite.config.js` does the same in `vite dev`
and `vite preview`, so local URLs match production.

### How content reaches the page

The API puts the published rows in a `<script id="__DATA__"
type="application/json">` block in each page's head.
[content.js](src/data/content.js) parses it and shapes it for the components
(services, projects, testimonials, brands, FAQs, contact details, stats). With
no block — `vite dev` on its own — it falls back to `site.js`, so the site
still renders for design work. Images from the API arrive as a `media` view
(ladder of AVIF/WebP/JPEG derivatives, dimensions, dominant colour) that
[Img.jsx](src/components/Img.jsx) turns into `srcset`.

### Project detail pages

`project.html` + [Project.jsx](src/pages/Project.jsx) render one project:
cover, story, gallery of renders, tags. The API fills the head tokens
(`__PROJECT_TITLE__`, `__PROJECT_DESCRIPTION__`, `__PROJECT_URL__`,
`__PROJECT_IMAGE__`), injects the project (with its gallery) into `__DATA__`
and answers unknown slugs with a 404 page. Cards and the sitemap link to
`/projects/<slug>`; no router is needed.

### The consultation modal

Every **"Book a Consultation"** CTA opens a modal enquiry form in place rather
than navigating. It is mounted once in [Layout.jsx](src/components/Layout.jsx)
and opened by a single delegated capture-phase listener in
[ConsultationModal.jsx](src/components/ConsultationModal.jsx) that matches a
trigger by its text — so a new CTA anywhere on the site works with no wiring.
Each CTA keeps `href="/contact"` as its fallback.

Scroll locking goes through [scrollLock.js](src/lib/scrollLock.js), which is
reference-counted on purpose: opening the modal from the mobile menu closes the
menu, and an uncounted `overflow = ''` on the menu's cleanup would release the
modal's lock a tick after it was taken.

### The enquiry form

[EnquiryForm.jsx](src/components/contact/EnquiryForm.jsx) and
[ConsultationModal.jsx](src/components/ConsultationModal.jsx) both post to
`contact.formEndpoint` (`/api/enquiries`, the studio API) through
[api.js](src/lib/api.js), with a honeypot field and a fill-time floor. The
API answers with a reference code the form shows. Validation is client-side;
messages are absolutely positioned so showing one can never shift the layout.
If the POST fails, the form falls back to a pre-filled email to `site.email`,
so no enquiry is lost.

## Before launch

1. **Domain** — replace `https://www.laspaceinteriors.in` in `index.html`,
   `src/data/site.js`, `public/robots.txt` and `public/sitemap.xml`.
2. **Contact details** — phone, WhatsApp number, email and postal address are
   placeholders in `src/data/site.js` and in the JSON-LD in `index.html`.
   The `geo` coordinates are approximate for Visakhapatnam.
3. **Images** — `public/images/` holds stand-in photography under the final
   filenames. Replace each file in place with the client's own; no code change
   needed. `og-cover.jpg` is the 1200×630 social card, and `work-01` … `work-12`
   are the portfolio grid.
4. **Logo** — `public/brand/logo.svg` and `monogram.svg` are text-built
   stand-ins; swap for the real marks.
4b. **Founder portrait** — the About page's founder card currently holds the
   monogram. Set `founder.portrait` in `src/data/site.js` to the real image
   path; `Shot` then renders it with `object-fit: cover` and the `alt` names
   Balachandu automatically.
5. **Social** — update the Instagram / Facebook / YouTube handles in
   `src/data/site.js` and the `sameAs` array in `index.html`.
6. **Contact page** — set `contact.mapsUrl` to the studio's real Google Maps
   listing, confirm `contact.hours`, and set `contact.formEndpoint` (see above).
